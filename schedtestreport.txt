3. 基于实际物理环境的测试验证
本次测试在实际物理单板上运行 Xvisor，并启动 Linux Guest OS。通过在 Xvisor 调度路径中设置 A、B、C 三个时间点，对一定测试周期内的中断处理延时和 vCPU 调度延时进行统计。
三个时间点定义如下：
	•	A 点：Timer Tick 中断进入 Hypervisor，开始执行本周期调度处理。
	•	B 点：中断分发及调度选择完成，并启动下一次调度 Timer。
	•	C 点：vCPU 上下文切换及 post-switch 处理完成，Guest OS 即将继续执行。
本文按以下工程测试口径划分：
中断延时 = B - A
调度延时 = C - B
测试工具在各 host CPU 上分别采集数据，最终对所有 host CPU 的样本进行全局汇总，统计平均值、最大值及有效样本数。
 
⸻
 
3.1 中断延时
● 测试分析
Timer Tick 中断到达后，处理器进入 Hypervisor 异常处理流程，并依次完成异常上下文保存、中断分发、Timer 回调、调度条件判断、就绪队列处理以及下一次调度 Timer 的配置。
因此，本测试将 A 点到 B 点之间的时间定义为中断延时：
T_{\mathrm{irq}}=T_B-T_A
该时间反映一次 Timer Tick 进入 Hypervisor 后，到本轮中断和调度前处理完成所产生的系统开销。其波动主要受到中断竞争、Hypervisor 临界区、调度队列状态和硬件运行状态等因素影响。
● 测试方案
	1.	在实际物理单板上启动 Xvisor 和一个 Linux Guest OS。
	2.	启用 A/B/C 调度延时测试功能。
	3.	执行以下命令进行短时测试：
lat_abc -t 10
	4.	执行以下命令进行约 25 小时的长时间稳定性测试：
lat_abc -t 1500
	5.	测试期间记录每次 A 点到 B 点的时间差，并统计全部 host CPU 样本的平均值和最大值。
● 测试结果
测试时长	最大中断延时	平均中断延时	样本数量
10 分钟	16.620 μs	0.967 μs	213,254
1500 分钟	25.900 μs	1.000 μs	32,058,060
● 测试结论
长时间测试共采集约 3205 万次有效样本，中断延时平均值约为 1.000 μs，最大值为 25.900 μs。
随着测试时间增加，最大值相较短时测试有所增大，这是由于长时间运行覆盖了更多偶发硬件中断、临界区竞争及系统抖动场景；但平均值仍稳定在约 1 μs，说明 Hypervisor 的 Timer Tick 中断处理开销整体较为稳定。
 
⸻
 
3.2 调度延时
● 测试分析
B 点完成下一次调度 Timer 的配置后，Hypervisor继续完成 vCPU 上下文切换，包括旧 vCPU 状态保存、新 vCPU 状态恢复、虚拟中断控制器恢复、系统寄存器恢复、VFP/SIMD 状态恢复、通用定时器恢复以及 Stage-2 地址空间切换等操作。
因此，本测试将 B 点到 C 点之间的时间定义为调度延时：
T_{\mathrm{sched}}=T_C-T_B
该时间表示 Hypervisor 完成调度选择和 Timer 配置后，到目标 vCPU 已完成上下文恢复、Guest OS 即将继续执行所需的时间。
● 测试方案
	1.	测试环境与中断延时测试保持一致。
	2.	使用 lat_abc 命令同步采集 B 点和 C 点时间戳。
	3.	对每次 B 点到 C 点的时间差进行统计。
	4.	对所有 host CPU 的样本进行全局汇总，计算平均调度延时和最大调度延时。
● 测试结果
测试时长	最大调度延时	平均调度延时	样本数量
10 分钟	15.600 μs	1.629 μs	213,254
1500 分钟	25.860 μs	1.769 μs	32,058,060
● 测试结论
长时间测试中，vCPU 调度延时平均值约为 1.769 μs，最大值为 25.860 μs。
调度延时平均值高于中断延时平均值，主要是因为该阶段包含完整的 vCPU 上下文保存与恢复、虚拟化寄存器切换以及可能的 TLB 刷新等操作。测试期间平均值保持在 2 μs 以内，表明 Xvisor 的 vCPU 调度切换开销整体稳定。
综合两段测试结果，一次 Timer Tick 到目标 vCPU 完成切换的平均 Hypervisor 开销约为：
T_{\mathrm{total,avg}} =T_{\mathrm{irq,avg}}+T_{\mathrm{sched,avg}} =1.000+1.769 =2.769\ \mu s
需要注意，两个阶段的最大值可能来自不同测试样本，因此不能直接将两个最大值相加作为单次完整调度链路的最大延时。
