下面按你当前模板给 vmm_scheduler.c 做单元测试设计。这个文件比前几个复杂很多，主要难点是：
	1.	struct vmm_scheduler_ctrl 和 sched 是本 .c 文件内部对象；
	2.	大量逻辑依赖 per-cpu 数据；
	3.	vmm_scheduler_state_change() 分支很多，且会触发抢占、IPI、ready queue 操作；
	4.	idle_orphan() 是无限循环函数；
	5.	BUG_ON 路径按你要求用 if (x) exit(0) 方式处理。
下面先给出最小 User Code，然后给出用例构造方法和注释。为避免测试用函数过多，User Code 中只定义变量和指针句柄，不定义复用 helper 函数。
 
⸻
 
一、公共 User Code 设置
1. Unit Prefix User Code
放到能影响 vmm_scheduler.c 的 Unit Prefix User Code 中。
#include <vmm_scheduler.h>
#include <vmm_vcpu_irq.h>
#include <vmm_cpumask.h>
#include <libs/list.h>

#ifdef BUG_ON
#undef BUG_ON
#endif

#define BUG_ON(x)              \
    do {                       \
        if (x) {               \
            exit(0);           \
        }                      \
    } while (0)
如果锁函数或 arch_cpu_irq_save/restore 会执行真实汇编，建议在 Stub 或 Prefix 中改成 no-op。
 
⸻

其中：
idle_orphan
是无限循环函数，必须使用桩函数受控退出。例如让 arch_cpu_wait_for_irq 或 vmm_scheduler_yield 第二次调用时 exit(0)。
vmm_scheduler_state_change() 建议按状态转换矩阵单独拆用例，例如：
NULL vcpu -> -1
UNKNOWN -> RESET，新 VCPU setup 成功
UNKNOWN -> RESET，setup 失败
RESET -> READY，enqueue 成功
PAUSED -> READY，enqueue 成功
RUNNING -> READY，resumed = TRUE，skip_state_change
READY -> READY，skip_state_change
READY -> PAUSED，detach 成功
RUNNING -> PAUSED，preempt = TRUE
PAUSED -> PAUSED，skip_state_change
READY/RUNNING -> HALTED
RUNNING 请求 RUNNING -> -5
非法转换 -> -5
halt_flag true 且状态回到 READY/RUNNING -> 自动二次转换 HALTED
如果你要，我下一步可以继续把 vmm_scheduler_state_change() 这个最大函数单独拆成完整状态转换用例矩阵，按你现在的格式给出每条构造和注释。
