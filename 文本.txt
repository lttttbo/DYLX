下面按你提供的两份源文件范围（vmm_scheduler.c + vmm_schedalgo_prr.c），把所有函数（含 static 内部函数与 #ifdef 条件函数）逐个做“设计/接口级”分析，并为每个函数给出 PlantUML 活动图（流程图）。
约定（便于文档一致性）
	•	输入参数：函数调用者提供（IN）
	•	输出参数：通过指针由函数写回（OUT），或通过返回值返回
	•	常见返回码（仅列本模块出现的）：
	•	VMM_OK：成功
	•	VMM_EFAIL：一般性失败（空指针/内部失败）
	•	VMM_EINVALID：参数/状态不合法
	•	VMM_ENOTAVAIL：资源/条件不可用（如队列空、CPU不在线等）
	•	VMM_ENOMEM：内存不足（只在 PRR setup/create 场景出现）
	•	VMM_VCPU_STATE_* 属于 vCPU 状态机常量（定义在头文件中），本文件直接使用：UNKNOWN/RESET/READY/RUNNING/PAUSED/HALTED 等。

2.8 __vmm_scheduler_next2（static）
功能 常规调度路径：在已有 current 的情况下，按“当前是否可保存/是否仍 RUNNING”决定是否将 current 重新入队，然后从队列中选出 next，必要时执行上下文切换，并启动 next 的时间片。
声明
static struct vmm_vcpu *__vmm_scheduler_next2(struct vmm_scheduler_ctrl *schedp,
                                              struct vmm_vcpu *current,
                                              arch_regs_t *regs);
输入参数（IN）
参数	类型	约束
schedp	struct vmm_scheduler_ctrl *	非空
current	struct vmm_vcpu *	非空
regs	arch_regs_t *	非空
输出参数（OUT）
输出	含义
返回值	若发生切换，返回 next；若未切换（next==current），返回 NULL（这是本函数的约定）
返回值（指针）
返回值	含义
NULL	next == current，本次不需要切换
非空	next != current，本次发生切换
流程图
@startuml
title __vmm_scheduler_next2 流程
start
:读取 current_state;
if (current_state 可保存?) then (是)
  if (current_state == RUNNING?) then (是)
    :同步系统时间到 current->system_nsecs;
    :RUNNING 时间累加;
    :设置 current 状态为 READY;
    :将 current 入队到就绪队列;
  endif
  :tcurrent = current(作为切换源);
endif

repeat
  :从就绪队列出队 next 与 time_slice;
  if (出队失败?) then (是)
    :触发 panic(不应发生);
    stop
  endif

  if (next != current?) then (是)
    :加 next->sched_lock(写锁);
    if (next 当前仍为 READY?) then (是)
      :arch_vcpu_switch(tcurrent, next, regs);
      :解 next->sched_lock(切换后再解);
      break
    else (否)
      :解 next->sched_lock;
      :继续重新出队选择 next;
    endif
  else (否)
    :next==current，无需切换;
    break
  endif
repeat while (需要重新选择?)

:更新 next 统计与状态(READY->RUNNING);
:设置 schedp->current_vcpu = next;
:启动时间片事件 ev(time_slice);
if (next != current?) then (是)
  :返回 next;
else (否)
  :返回 NULL;
endif
stop
@enduml

输出参数（OUT） 无（更新 per-cpu 当前 vCPU、启动定时器事件等）
返回值 void
流程图
@startuml
title vmm_scheduler_switch 流程
start
if (regs 是否为空?) then (是)
  :panic(不应发生);
  stop

:current = schedp->current_vcpu;

	•	SMP 场景下通过 IPI 触发对端重调度/迁移

输入参数（IN）

new_state	u32	典型取值：VMM_VCPU_STATE_UNKNOWN/RESET/READY/PAUSED/HALTED（RUNNING 不允许外部直接设置）

输出	说明

流程图（抽象但覆盖关键分支）
@startuml
title vmm_scheduler_state_change 主流程(抽象覆盖关键分支)
start
if (vcpu 是否为空?) then (是)
  :返回 VMM_EFAIL;
  stop
endif

repeat
  :保存/关中断，写锁 vcpu->sched_lock;
  :读取 vhcpu=vcpu->hcpu 与 current_state;
  :根据 new_state 进入分支处理;

  if (new_state==UNKNOWN?) then (是)
    :调用 schedalgo_vcpu_cleanup;
  elseif (new_state==RESET?) then (是)
    :新建或重置路径\nsetup/清队列/arch_vcpu_init/vcpu_irq_init;
  elseif (new_state==READY?) then (是)
    :从 RESET/PAUSED 入队 ready queue;\n必要时设置 preempt;
  elseif (new_state==RUNNING?) then (是)
    :直接返回 VMM_EINVALID;
  elseif (new_state==PAUSED 或 HALTED?) then (是)
    :若从 READY/RUNNING 进入\n则 detach 或触发 preempt;
  else (其他)
    :rc=VMM_EINVALID;
  endif

  :若 rc==OK\n则对旧状态做时间补账\n写入新状态与 state_tstamp;
  :解锁 vcpu->sched_lock，按需触发本核/跨核抢占(resched);
  :若 rc!=OK 则打印失败日志;

  if (满足 halt_flag 二次进入条件?) then (是)
    :清除 halt_flag;
    :new_state = HALTED;
  else (否)
    break
  endif
repeat while (需要二次执行?)

:返回 rc;
stop
@enduml
备注（你写文档时建议写清的“契约”）
	•	RUNNING 状态只能由 context switch 设置，外部请求 RUNNING 会返回 VMM_EINVALID（代码已明确）。
	•	READY/HALTED/PAUSED 的合法性与队列操作强绑定：READY 会 enqueue；离开 READY 会 detach；RUNNING→PAUSED/HALTED 会触发抢占。
