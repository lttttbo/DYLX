下面按你现在确认的原则，重新给出 psci.c 的单元测试方案：
1. PSCI helper 尽量真实执行，不再默认 stub。
2. 只 stub manager / 系统副作用 / 等待中断 / 打印类外部依赖。
3. 不再重定义 vmm_manager_for_each_guest_vcpu 宏，而是 stub 它内部调用的 vmm_manager_guest_next_vcpu。
4. 入参通过真实 vmm_vcpu、vmm_guest、arm_priv、arm_guest_priv、arch_regs_t 构造。
5. 期望返回值尽量给具体数值。
6. 注释中说明每条用例覆盖目的。
 
⸻
 
一、User Code 修改方案
1. Test Case Header User Code
目的：让 Test Case Init / Value User Code 可以使用 memset。
#include <string.h>
如果你的环境已经有 memset 声明，可以不加。
 
⸻
 
2. User Global / Data
目的：只保留外部 manager stub 所需的简单控制变量；不定义完整结构体对象，避免不完整类型或链接作用域问题。
void *vcast_psci_vcpus[4];
unsigned int vcast_psci_vcpu_count;

unsigned int vcast_psci_state[4];

int vcast_psci_vcpu_reset_rc;
int vcast_psci_vcpu_kick_rc;
int vcast_psci_guest_shutdown_rc;
int vcast_psci_guest_reboot_rc;
int vcast_psci_guest_suspend_rc;
 
⸻
 
3. Unit Prefix User Code
目的：提供少量构造宏，避免每条用例直接依赖你工程里 ARM 私有字段的具体名字。
你当前 emulate_psci_get_mpidr() 是：
return arm_priv(vcpu)->cp15.c0_mpidr;
所以这里按 cp15.c0_mpidr 写。如果你的实际编译单元里是 sysregs.mpidr_el1，只需要改这一处宏即可。
#define VCAST_SET_MPIDR(_priv, _val) \
    ((_priv).cp15.c0_mpidr = (unsigned long)(_val))

#define VCAST_SET_BE(_regs) \
    ((_regs).cpsr |= CPSR_BE_ENABLED)

#define VCAST_GET_BE(_regs) \
    ((_regs).cpsr & CPSR_BE_ENABLED)

#define VCAST_GET_THUMB(_regs) \
    ((_regs).cpsr & CPSR_THUMB_ENABLED)
如果你的 arch_regs_t 实际只有 pstate，则把上面三个 cpsr 改成 pstate。
 
⸻
 
4. Stub：
vmm_manager_guest_next_vcpu
目的：保留源码里的真实宏：
vmm_manager_for_each_guest_vcpu
只替换其外部 manager 依赖函数，使遍历顺序可控，避免构造真实链表和锁。
 
Stub User Code：
unsigned int i;

if (!guest) {
    return (struct vmm_vcpu *)0;
}

if (!current_vcpu) {
    if (vcast_psci_vcpu_count == 0U) {
        return (struct vmm_vcpu *)0;
    }

    return (struct vmm_vcpu *)vcast_psci_vcpus[0];
}

for (i = 0U; i < vcast_psci_vcpu_count; i++) {
    if (current_vcpu == (struct vmm_vcpu *)vcast_psci_vcpus[i]) {
        if ((i + 1U) < vcast_psci_vcpu_count) {
            return (struct vmm_vcpu *)vcast_psci_vcpus[i + 1U];
        }

        return (struct vmm_vcpu *)0;
    }
}

return (struct vmm_vcpu *)0;
 
⸻

3. 期望值中的负数写入寄存器
因为 emulate_psci_set_reg() 最终调用：
cpu_vcpu_reg_write(vcpu, regs, reg, (u32)val);
所以负数写回到 regs.gpr[0] 时通常是 32-bit 扩展后的值：
-1 -> 0xFFFFFFFF
-3 -> 0xFFFFFFFD
-6 -> 0xFFFFFFFA
如果你的 cpu_vcpu_reg_write() 实际会符号扩展到 64-bit，则期望要改为：
-1 -> 0xFFFFFFFFFFFFFFFF
-3 -> 0xFFFFFFFFFFFFFFFD
-6 -> 0xFFFFFFFFFFFFFFFA
建议你先用一个 emulate_psci_0_2_call 的 NOT_SUPPORTED 用例确认实际写回形式。
