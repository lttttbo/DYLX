你补充的这个信息非常关键：
dsm 在 STR 流程中也是冻结再拉起，pid 不变
这说明：
	•	virtio_net_teardown() 大概率不会执行（因为进程没有退出，设备对象仍存在）。
	•	tap1 被删除/脱离 br0 的原因更可能来自：
	1.	Linux bridge 在 suspend/resume 后重新处理 netdevice 状态
	2.	tap1 收到了 NETDEV_DOWN / NETDEV_UNREGISTER
	3.	vhost-net/tap backend 在恢复过程中被 reset
	4.	ServerVM 网络恢复流程主动 remove/add bridge port
	5.	Xvisor/acrn-dm 恢复时触发 virtio reset，导致 tap 状态变化
现在应该从“生命周期”角度打日志，而不是继续看 IP。
 
⸻
 
一、首先确认 tap1 是“消失”还是“脱离 bridge”
你现在看到：
brctl show br0
tap1 不在。
但是需要确认：
情况 A
tap1 设备不存在：
ip link show tap1
没有输出。
说明：
tap1 unregister
 
⸻
 
情况 B
tap1 还存在：
ip link show tap1
有：
tap1: <BROADCAST,MULTICAST>
但是：
brctl show br0
没有 tap1。
说明：
bridge port detach
这两个完全不同。
 
⸻
 
二、dsm virtio-net 增加日志
1. tap 创建/打开
位置：
static int
virtio_net_tap_open(char *devname)
在：
rc = ioctl(tunfd, TUNSETIFF, (void *)&ifr);
之后：
增加：
pr_err("DM: tap open success name=%s fd=%d\n",
       ifr.ifr_name, tunfd);
目的：
确认 STR 后有没有重新创建 tap。
 
⸻
 
2. tap fd 关闭
重点位置：
virtio_net_teardown()
改：
static void
virtio_net_teardown(void *param)
{
    struct virtio_net *net;

    net = (struct virtio_net *)param;

    pr_err("DM: virtio_net_teardown tapfd=%d\n",
           net ? net->tapfd : -1);

    if (!net)
        return;

    if (net->tapfd >= 0) {
        pr_err("DM: closing tap fd=%d\n", net->tapfd);
        close(net->tapfd);
        net->tapfd = -1;
    }

    virtio_reset_dev(&net->base);
    free(net);
}
如果 STR 后没有这个打印：
说明不是 teardown。
 
⸻
 
三、重点增加 virtio reset 日志
位置：
static void
virtio_net_reset(void *vdev)
增加：
static void
virtio_net_reset(void *vdev)
{
    struct virtio_net *net = vdev;

    pr_err("DM: virtio_net_reset enter "
           "tapfd=%d rx_ready=%d resetting=%d\n",
           net->tapfd,
           net->rx_ready,
           net->resetting);
恢复结束：
pr_err("DM: virtio_net_reset exit "
       "rx_ready=%d\n",

这里：

如果 reset 后：
没有：

那么：
tap 存在，但是网络不通。

八、我目前重新排序怀疑点
