3. 修改现有 
vcast_manager_prepare_guest_env
为了测试 Guest 重复检查，需要使 guest_count 个 Guest 真正进入 mngr.guest_list。
将该函数的 Guest 初始化部分调整为：
void vcast_manager_prepare_guest_env(u32 guest_count)
{
    u32 g;

    memset(vcast_guest_array,
           0,
           sizeof(vcast_guest_array));

    memset(vcast_guest_avail_array,
           0,
           sizeof(vcast_guest_avail_array));

    memset(vcast_guest_work_store,
           0,
           sizeof(vcast_guest_work_store));

    INIT_LIST_HEAD(&mngr.guest_list);

    for (g = 0U;
         g < (u32)CONFIG_MAX_GUEST_COUNT;
         ++g) {
        INIT_LIST_HEAD(&vcast_guest_array[g].head);

        vcast_guest_array[g].id = g;
        vcast_guest_avail_array[g] = TRUE;

        /*
         * guest_count 个 Guest 视为当前已占用，
         * 同时加入 mngr.guest_list。
         */
        if (g < guest_count) {
            vcast_guest_avail_array[g] = FALSE;

            list_add_tail(
                &vcast_guest_array[g].head,
                &mngr.guest_list);
        }
    }

    mngr.guest_array = vcast_guest_array;
    mngr.guest_avail_array =
        vcast_guest_avail_array;
    mngr.guest_work_array =
        &vcast_guest_work_store[1];

    mngr.guest_count = guest_count;

    vcast_expected_guest = NULL;
}

三、通用配置
1. 字符串函数必须使用 Actual
以下函数不能保留默认返回 0 的 Stub：
strcmp
strncmp
strlcpy
strlcat
memset
memcpy
至少在本函数测试中设置为 Actual，否则：
	•	Guest/VCPU 类型判断失真；
	•	Guest 名称不会真正复制；
	•	VCPU 名称过长路径无法正确产生；
	•	最终返回对象内容不正确。
 
⸻
 
2. 建议统一设置为空实现或固定成功
vmm_manager_lock                         空实现
vmm_manager_unlock                       空实现
vmm_devtree_ref_node                     空实现
vmm_devtree_dref_node                    空实现
platform_pt_notify_guest_add             空实现
vmm_scheduler_set_hcpu_raw               空实现
vmm_scheduler_set_state_raw              空实现
vmm_free                                 空实现
arch_vcpu_deinit                         空实现
vmm_vcpu_irq_deinit                      空实现
gpio_key_init                            空实现
vmm_manager_guest_destroy                返回 VMM_OK
__vmm_manager_good_hcpu                  返回 0
vmm_timer_timestamp                      返回 0x12345678
gpio_key_init() 已经单独测试，本 UUT 中应 Stub，避免其设备树调用干扰 getchild/getattr 的返回序列。
 
⸻
 
3. cpumask inline 函数
以下 inline 函数通过展开后的非 inline 子函数控制：
vmm_cpumask_weight   -> __bitmap_weight
vmm_cpumask_subset   -> __bitmap_subset
vmm_cpumask_equal    -> __bitmap_equal
不要直接 Stub inline 函数。
特别注意：
vmm_devtree_read_u32_atindex
在返回一次 VMM_OK 后必须再配置一次非零返回值结束循环，否则默认返回 0会导致无限循环。
 
⸻

十一、不可达或需说明的路径
1. 最小优先级判断 true 不可达
if (vcpu->priority < VMM_VCPU_MIN_PRIORITY)
当前定义：
#define VMM_VCPU_MIN_PRIORITY 0
而：
vcpu->priority
类型为 u8，最小值也是 0，因此不存在：
priority < 0
的输入。该判断 true 路径结构性不可达。
 
⸻
 
2. Guest 分配失败复合条件
if (!guest ||
    gnum == CONFIG_MAX_GUEST_COUNT)
由于前面使用：
list_for_each_entry(guest, ...)
部分链表宏在循环结束后会使 guest 保留为内部哨兵计算地址，而不是 NULL。因此无可用槽位时，实际常通过：
!guest == false
gnum == CONFIG_MAX_GUEST_COUNT == true
进入失败路径。
若覆盖报告显示 !guest=true 缺失，这通常是链表迭代宏语义导致，不是输入遗漏。
 
⸻
